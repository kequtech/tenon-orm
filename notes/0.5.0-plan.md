# Tenon 0.5.0 scope

Prepared versions: Tenon 0.5.0, pgclear 0.3.5 and pgclear-jobs 0.2.1. Nothing is published.
The release responds to consuming applications' 0.4.11 reviews, which found integration friction
but no reproducible library correctness blocker in their exercised workflows.

## Accepted decisions

| Change                                  | General reason                                                               |
| --------------------------------------- | ---------------------------------------------------------------------------- |
| Documentation rewrite                   | Make common workflows discoverable and give each detailed contract one owner |
| Bulk job lookup                         | Avoid N+1 operational-state reads                                            |
| Scheduled keyed requests                | Let scheduled/manual/startup triggers use the same durable request identity  |
| Original driver-error traversal         | Reuse operation evidence without inventing a whole-transaction outcome       |
| Optional readiness/lifetime handle      | Separate host startup from worker supervision using the same runner          |
| Finite identifier parameters            | Check bounded ordinary helpers without interpreting application code         |
| Grants/storage upgrade/hosting examples | Make real ownership and deployment boundaries reproducible                   |

These capabilities are implemented. Exact APIs belong in their current guides, not this scope note.
The [boundary review](../CONSIDERATIONS.md) records code, documentation and test ownership.
[Contributor instructions](../CONTRIBUTING.md) describe packed-candidate testing and the remaining
registry-only verification after the supporting patches are published.

## Deferred requests

- **Running cancellation:** useful capacity control, but it changes claim ownership and completion
  races. A design must define durable cancellation intent/acknowledgement, cross-process signals,
  managed rollback, stale completion, retries/history and successor promotion. Lost notifications
  cannot lose cancellation intent. Uncooperative JavaScript must not free a local slot while still
  running, and external effects remain cooperative. Keep pending-only cancel until that contract exists.
- **Pagination iterator:** cursor find plus bulk lookup addresses current needs. Add another API only
  if consumers still repeat meaningful iteration code incorrectly.
- **Storage namespaces:** isolated test databases and the fixed production schema cover demonstrated
  use. Reconsider only for independent queue installations within one physical database.

Automatic migrations, transaction replay, process management, stored business results and generalized
application repair remain outside library scope. Applications retain authorization, business IDs,
results and external-effect reconciliation. No framework or configuration layer is needed for these
requests.
