# Tenon 0.5 release scope

Current targets: Tenon 0.5.1, pgclear 0.3.6 and pgclear-jobs 0.3.0. Keep the repositories
independent and consume their public packages. Publication remains a separate explicit action.

The 0.4.11 and 0.5.0 consumer reviews found integration friction rather than a reproducible
library correctness blocker. The accepted work preserves explicit SQL, scopes and original errors.

## Included

- Seven Tenon task guides, concise standalone driver/Jobs guides, and detailed contracts in the
  owning package. Use installed-documentation paths and immutable cross-package source references.
- Bulk lookup, keyed schedules, readiness/lifetime handles and original driver-error traversal.
- Finite identifier parameters in source checks; unsupported composition remains visibly unchecked.
- Per-query signal/timeout options across ordinary queries, guards and Tenon's transaction queue.
- Durable cross-process job cancellation through cancel(id), the existing handler signal and
  heartbeat. Storage version 3 adds intent and cancelled attempt history. Application-owned SQL
  migrations handle existing-storage changes without rewriting old files. Jobs exports only its
  canonical current up/down pair.
- Concise checker output with detailed verbose/JSON reports; a worked unchecked-query policy.
- An installed-package database-test example and a migration/freshness/typecheck/test CI recipe.
- Existing optional hosting examples, readiness limits, runtime grants and isolated consumer tests.

The [boundary review](../CONSIDERATIONS.md) records ownership. [Contributor instructions](../CONTRIBUTING.md)
cover packed-candidate validation. No upgrade command is needed for infrequent storage changes;
applications author occasional changes by comparing saved storage with the canonical schema.

## Deferred

- Pagination helpers: bounded getMany and cursor find remain sufficient primitives.
- Storage namespaces: use isolated databases or shared storage with deliberate ownership for now.
- Broader checker interpretation: improve explanations before interpreting arbitrary helper bodies.

Business results, authorization, provider idempotency, stale-result fences, host restart policy and
external-effect reconciliation remain application-owned. Cancellation is cooperative and cannot
prove an arbitrary JavaScript callback or remote effect has stopped. No automatic callback replay,
relationship framework, process manager or runtime row-validation layer is introduced.
